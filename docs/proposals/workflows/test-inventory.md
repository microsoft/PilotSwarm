# Workflow test inventory

This file answers which tests cover Workflows and which provider runs select them. For example, `workflow-control.test.js` exercises pause and cancel with real Duroxide and PostgreSQL, not a real model.

Source: commit `4fa702dc8b078b93c3e26339dc833b53d8acfee4`. This is a static inventory, not a report that these tests passed.

## Reading the inventory

Each row names one file and quotes representative suite or case titles from that file. The linked line is the first listed title. Tier describes the strongest facility the file invokes, including calls to local helpers. A file can also contain lower-tier cases. Unit means no real database or runtime is required; Local PostgreSQL means real SQL without a native orchestration runtime; Real Duroxide includes native runtime/worker scenarios with scripted or absent models; Real model means an unscripted model scenario that runs in every full pass. Source-only checks under the local runner remain Unit. Local process/CLI cases use real subprocesses or the Copilot CLI with a scripted provider, but no real database or Duroxide; they are not mislabeled real-model tests.

Provider selection is literal membership: [`scripts/test-provider-plan.mjs:43`](../../../scripts/test-provider-plan.mjs#L43) selects every SDK local test except `baselineOnly` in [`scripts/provider-test-coverage.json:1`](../../../scripts/provider-test-coverage.json#L1). This storage-provider policy is separate from live-model execution: live-model tests have no opt-in gate and fail with `BLOCKED: no usable model: <why>` if their model or credential is unavailable. Unit files are outside that local selector. Settings below configure the model, effort, samples, receipt and target, not whether a live test runs. Common setup is in [`workflow-real-model.mjs`](../../../packages/sdk/test/helpers/workflow-real-model.mjs).
