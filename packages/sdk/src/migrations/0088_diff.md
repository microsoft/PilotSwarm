# Diff for migration 0088

Migration: `package-runtime-procedures-0088.ts`, `packageRuntimeProceduresMigration`.
Design: `docs/proposals/executable-package-authorization.md`.

## Deploy and rollback requirements

Run the additive migration before the matching provider code admits package
execution. Automatic CMS initialization applies 0084–0088 in order. This changes
no tables, existing function bodies, triggers, permissions or historical rows.
Each procedure is idempotent `CREATE OR REPLACE`, schema-qualified and returns
`SETOF JSONB`; the TypeScript transport retains existing row mapping. Explicit
BIGINT audit IDs are serialized as text to avoid JSON precision loss.

Keep the existing mixed-fleet and legacy-worker gate: stored procedures and
verified source snapshots do not fence unknown legacy code. Old runtime workers
must be stopped/fenced before release qualification. There is no destructive down
migration; retained functions are harmless on rollback, while deleting
registration/grant/audit/legacy evidence is not a rollback mechanism.

## Table, column, index and trigger changes

None. All 33 functions are new, so there is no replaced-function baseline diff.
They move the existing provider's reads/writes behind the stored-procedure
boundary without moving or splitting the transaction. DML functions use a
`RETURNING` CTE so result row counts retain CAS/acknowledgement semantics.

## Mapping and ordering

| Operations | Existing behavior retained |
|---|---|
| eligible / has_pin / access / owner / binding / grant / capabilities / package / inspection / version | Exact approved identity, current owner/visibility/agent, version/grant and capability metadata reads; **no metadata tuple locks**. |
| register / live / heartbeat | Generation identity and lease bookkeeping; `live` alone retains `FOR UPDATE` on the runtime registration, not metadata. |
| request_fence / ack_fence / registration / processes / note_process / recoverable / local_processes | Denial-first state, exact process identity and truthful exit acknowledgements; no timeout-as-proof conversion. |
| eligibility / outstanding / legacy_count | Current denial and incomplete fencing/fleet status. |
| unselect / select_grant / grant_audit / capabilities_cas / capabilities_update | Exact selected identities, expected capability revision, current owner and atomic grant/capability replacement with append-only history. |
| reviews / review_audit / activation_audit / runtime_supported | Authenticated administrative review inventory, append-only audit reads and runtime-support discovery. |
| audit | Existing admission/completion audit insertion. |

`PgPackageRuntimeAuthority` still acquires the schema admission barrier **before**
its ordered operations. `PgSessionCatalog.saveSessionCapabilities`
keeps its barrier, capability CAS and `syncSelectionGrants` in the same
transaction/client. Admission's metadata reads remain nonlocking, preserving the
0087 writer-row-lock/barrier ordering regression. Procedure calls are an internal
database/provider boundary, not a new grant of SQL credentials to package code.
Server-side administrator identity checks and existing review/activation/rebind
procedures remain unchanged.

Real standalone PostgreSQL acceptance covers migration reapplication, approval
and activation CAS, exact-version pins, grants/capability atomicity, concurrent
metadata writers, revocation, multiple workers and process recovery through these
procedures. The source guard prevents table-access SQL from returning to the
new authority/review providers.
