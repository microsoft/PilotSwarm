# Diff for migration 0082

Migration: `migrations/session-steering-0082.ts` — `sessionSteeringMigration`.
Design: `docs/proposals/session-steering.md` §6a.2, §6a.3 and §7.3.

Additive. It creates the steering ledger, the admission windows and the `cms_steer_*`
procedures. It replaces three existing procedures with their latest bodies plus a
steering backstop. It publishes the feature flag `sessions.steering` (Off, no user
override). No earlier migration is edited.

## Table, sequence and index changes

| Object | Change |
|---|---|
| `session_steering_seq` | New sequence. Server order of steers (FR-6). |
| `session_steering_requests` | New table. One row per accepted steer; the only acceptance authority. `UNIQUE (session_id, idempotency_key)`. FK to `sessions` with `ON DELETE CASCADE`. CHECK constraints on `status`, `recovery_check`, `included`, `closure_reason` and `disposition`. |
| `session_steering_attempts` | New table. Append-only hand-off history; one row per `send()` attempt. `UNIQUE (request_id, attempt_no)`, `UNIQUE (request_id, sdk_message_id)`. |
| `session_steering_windows` | New table. One row per target `(session_id, transcript_epoch, turn_index, incarnation)`. Closed rows are tombstones. Partial unique index `session_steering_windows_one_live` allows at most one non-closed window per session. |
| `session_steering_counters` | New table. Cumulative pre-acceptance counters (`duplicate`, `rejected:<code>`). No content. |
| Indexes | `session_steering_requests_by_seq (session_id, seq)`, `..._by_target (session_id, epoch, turn, incarnation, seq)`, `..._by_actor ((actor->>'provider'), (actor->>'subject'), accepted_at)` for the per-actor rate, `session_steering_attempts_by_session (session_id, submitting_at)`. |

## Feature flag

`feature_flags`: inserts `sessions.steering` (`default_enabled = false`,
`default_allow_user_override = false`, `required_capability = 'sessions.steering'`).
`feature_flag_settings`: inserts the cluster row (`enabled = false`,
`allow_user_override = false`, `updated_by = 'migration:0082'`). Both use
`ON CONFLICT DO NOTHING`, as migration 0081 does.

## New functions

All new. Lock order in every procedure: actor advisory lock (acceptance only) →
session steering advisory lock (`cms_steer_lock_session`) → window row → request
rows → attempt rows.

| Function | Purpose |
|---|---|
| `cms_steer_iso(ts)` | ISO-8601 UTC text for receipts. |
| `cms_steer_target_token(session, epoch, turn, incarnation)` | Opaque `expectedTarget`: `st1.` + base64url of the four fields joined by newline. `steering.ts` uses the same encoding. |
| `cms_steer_lock_session(session)` | Transaction advisory lock for one session's steering state. |
| `cms_steer_count(session, name)` | Increments a counter. |
| `cms_steer_closed_disposition(request, reason, current)` | Terminal disposition from evidence only (§6a.2 table). Also corrects a closed row's historical label when late evidence arrives. |
| `cms_steer_projection(request, with_text, attempt_after, attempt_limit)` | The receipt (`SteeringReceiptV1` without `actions`). Derives eligibility, inclusion, submission evidence, `recovering` and the recovery flags. One source for reads and events. |
| `cms_steer_record_event(session, type, ref, data)` | Inserts `session.steering_accepted` / `session.steering_updated` (derived from `ref`) or a given payload, in the caller's transaction. |
| `cms_steer_window_event(session, state, token, reason)` | Inserts `session.steering_window_changed`. |
| `cms_steer_match_or_conflict(row, actor, hash, epoch, turn, incarnation)` | Same actor, hash and target ⇒ receipt (`duplicate: true`); otherwise `idempotency_conflict` with no fields of the existing row. |
| `cms_steer_close_target(session, epoch, turn, incarnation, reason, window_reason)` | Shared terminal closure of one target. |
| `cms_steer_close_session(session, reason)` | Closes every live target of a session (terminal-state and delete backstop). |
| `cms_steer_accept(...)` | §7.3 sketch. Adds: `forbidden` without a canonical actor, `invalid` for an empty body, `not_found` for a missing or deleted session, `too_large` by UTF-8 bytes, `rate_limited` with reason `unresolved_cap` or `actor_rate`. Raises `pg_notify('pilotswarm_steering', session_id)`. |
| `cms_steer_window_open(...)` | Refuses a closed tombstone or an older `(epoch, turn)`; same target ⇒ recovery (rows → `orphaned`, `recovery_check = pending` when an SDK id exists); new target ⇒ closes other live targets (`turn_ended`, window reason `superseded`), then inserts `open`. |
| `cms_steer_window_abandon(...)` | Writes a `closed` tombstone (`abandoned`) when absent, or closes the target when still owned by the caller. |
| `cms_steer_window_renew(...)` | Lease extension for the owner of an `open` or `quiesced` window. |
| `cms_steer_window_quiesce(...)` | `open` → `quiesced`. Rows untouched. |
| `cms_steer_window_adopt(...)` | Already-committed path: owner takeover to `quiesced` with an expired lease; never for a closed or older target. |
| `cms_steer_claim(...)` | Owner of an `open`, lease-fresh window: `pending` and eligible `orphaned` rows → `claimed`, in `seq` order, `FOR UPDATE SKIP LOCKED`. Returns only the rows claimed by this call. |
| `cms_steer_record_recovery_check(...)` | `present` ⇒ delivered + `included`; `absent` ⇒ re-claimable; `failed` ⇒ unclaimable. |
| `cms_steer_mark_submitting(...)` | The write-ahead attempt row; requires an `open` window and claim ownership. Returns the attempt id. |
| `cms_steer_mark_released(...)` | Attempt `released`; row back to `pending` (owner only). |
| `cms_steer_mark_submitted(...)` | Records the SDK id; only the current owner's row advances. |
| `cms_steer_mark_delivered(...)` | Idempotent delivery evidence plus the single `user.message` projection with `data.steering`. A stale owner's evidence is history only. |
| `cms_steer_mark_unconfirmed(...)` | Attempt `unconfirmed`. |
| `cms_steer_turn_finalize(...)` | Owner-fenced inclusion from the commit outcome, then terminal close (`turn_ended`). Refinement of the §7.3 sketch: a row with no possible send is `not_included` whatever the outcome; with a manifest, a row not in it is `not_included` only after a recovery check proved it `absent` and this owner did not resend it, otherwise `unconfirmed`. |
| `cms_steer_close_stopped(session, turn)` | Target-scoped Stop closure, all non-terminal rows of that turn index. |
| `cms_steer_withdraw(...)` | Author or manager; `pending` → `withdrawn`; else `not_withdrawable` / `already_settled`. |
| `cms_steer_get`, `cms_steer_list`, `cms_steer_state`, `cms_steer_stats` | Receipt, page (cap 200), window state with the current token, aggregates. |

## Replaced functions

### `cms_record_events` — body extended (baseline: 0004)

Same insert. Adds the durable Stop authority: each `session.turn_stopped` event with a
numeric `data.turnIndex` closes that turn's steering in the same transaction.

```diff
--- 0004
+++ 0082
@@
 ) RETURNS VOID AS $$
+DECLARE v_turn TEXT;
 BEGIN
     INSERT INTO SCHEMA.session_events (session_id, event_type, data, worker_node_id)
     SELECT
         p_session_id,
         (elem->>'eventType'),
         (elem->'data'),
         p_worker_node_id
     FROM jsonb_array_elements(p_events) AS elem;
+
+    IF jsonb_typeof(p_events) = 'array' AND p_events @> '[{"eventType":"session.turn_stopped"}]'::JSONB THEN
+        FOR v_turn IN
+            SELECT elem->'data'->>'turnIndex' FROM jsonb_array_elements(p_events) AS elem
+             WHERE elem->>'eventType' = 'session.turn_stopped'
+               AND (elem->'data'->>'turnIndex') ~ '^-?[0-9]{1,9}$'
+        LOOP
+            PERFORM SCHEMA.cms_steer_close_stopped(p_session_id, v_turn::INT);
+        END LOOP;
+    END IF;
 END;
 $$ LANGUAGE plpgsql;
```

### `cms_update_session` — body extended (baseline: 0059)

Same updates. Adds the terminal-state backstop. It acts only on `failed`, `cancelled` and
`completed`; never on `idle`, `waiting`, `input_required` or `error`, which can arrive
while a turn is commit-pending.

```diff
--- 0059
+++ 0082
@@
     UPDATE SCHEMA.session_metrics
        SET model = CASE WHEN p_updates ? 'model' THEN (p_updates->>'model') ELSE model END,
            reasoning_effort = CASE WHEN p_updates ? 'reasoningEffort' THEN NULLIF(BTRIM(p_updates->>'reasoningEffort'), '') ELSE reasoning_effort END,
            updated_at = CASE WHEN p_updates ? 'model' OR p_updates ? 'reasoningEffort' THEN now() ELSE updated_at END
      WHERE session_id = p_session_id
        AND (p_updates ? 'model' OR p_updates ? 'reasoningEffort');
+
+    IF (p_updates ? 'state') AND (p_updates->>'state') IN ('failed', 'cancelled', 'completed') THEN
+        PERFORM SCHEMA.cms_steer_close_session(p_session_id, 'session_' || (p_updates->>'state'));
+    END IF;
 END;
 $$ LANGUAGE plpgsql VOLATILE;
```

### `cms_soft_delete_session` — body extended (baseline: 0004)

Same soft delete. A deleted session's live steering targets close (`turn_ended`, window
reason `session_deleted`).

```diff
--- 0004
+++ 0082
@@
     UPDATE SCHEMA.session_metric_summaries
     SET deleted_at = now(), updated_at = now()
     WHERE session_id = p_session_id;
+
+    PERFORM SCHEMA.cms_steer_close_session(p_session_id, 'session_deleted');
 END;
 $$ LANGUAGE plpgsql;
```

`cms_steer_close_session` returns before taking any lock when the session has no live
window and no unresolved request, so the backstops cost one indexed lookup for
sessions that never steered.
