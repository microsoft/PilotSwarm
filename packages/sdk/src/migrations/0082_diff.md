# Diff for migration 0082

Migration: `migrations/turn-control-0082.ts` — `turnControlMigration`, registered as `0082 turn_control`.
Design: `docs/proposals/session-turn-control.md` (sections 4.1, 4.2, 5.2, 5.3) and plan decisions P5, P13, P17 (amendment S1), P19, P20 in `.paw/work/turn-control/ImplementationPlan.md`.

## Table and index changes

| Change | Detail |
|---|---|
| `sessions.turn_high INTEGER NOT NULL DEFAULT -1` | The highest turn started on the turn-control path in this orchestration lifetime. `turn_high = active_turn_index` marks a running turn that accepts Stop and Steer. |
| `sessions.turn_base_seq BIGINT NOT NULL DEFAULT 0` | The last `session_events.seq` of earlier orchestration lifetimes. Every turn-control procedure ignores events at or below it. (Delta to design 4.1, plan P19.) |
| Indexes | None new. Reads use `session_events (session_id, event_type, seq)` from 0025. |

New event types (data only, no schema change): `user.steer`, `user.stop`, `session.control_outcome`, `session.carried_steers_closed`. The worker writes `session.steer_confirmed` through the existing `cms_record_events`.

## New functions

| Function | Role |
|---|---|
| `cms_turn_base_seq(p_session)` | Current lifetime base, 0 for a missing row. |
| `cms_turn_open_controls(p_session, p_turn)` | Open controls of one turn: `(seq, kind, text, created_at)`. Design 4.2 returns three columns; `created_at` is a deliberate delta for latency evidence (plan A2, P13). |
| `cms_turn_open_controls_json(p_session, p_turn, p_after)` | The same as JSON `{seq, kind, text, createdAt}`, after a position. |
| `cms_turn_is_stopped(p_session, p_turn)` | A `stopped` outcome exists for the turn in this lifetime. |
| `cms_turn_unclosed_carried(p_session)` | Steers with outcome `carried` and no `session.carried_steers_closed` record in this lifetime. |
| `cms_turn_close_all(p_session, p_reason)` | Every open control gets `stopped` (Stop) or `not_delivered` (Steer); unclosed carried steers get one closing record with `p_reason`. Caller holds the row lock. |
| `cms_turn_lifetime_reset(p_session)` | Before a soft-deleted row is revived: `cms_turn_close_all(..., 'terminal')`, then `turn_high = -1`, `active_turn_index = NULL`, `turn_base_seq = MAX(seq)`. No-op for a live or missing row. |
| `cms_turn_control_add(p_session, p_kind, p_text, p_request_id, p_actor, p_steering_allowed DEFAULT true)` | Design 4.2, with the lifetime base on the request-id lookup. Locks the row, refuses `not_found`; returns the first answer for a retried id in this lifetime (or refuses `request_id_reused`); then refuses a new Steer with `steering_disabled` when `p_steering_allowed` is false (a Stop ignores it, a lost-response retry keeps its first answer after the flag is turned off); then refuses `no_turn`, `legacy_turn`, `too_many`; writes `user.steer`/`user.stop`, notifies `pilotswarm_turn_control` with `{schema, sessionId}`. The caller passes the resolved `sessions.steering` flag. |
| `cms_turn_start(p_session, p_turn)` | Design 4.2. Locks the row; `{stale}` for an older turn; sets `active_turn_index` and `turn_high`; returns `{stopped, controls}`. A missing row returns no controls and writes nothing (today's `cms_set_active_turn_index` is a no-op there too). |
| `cms_turn_look(p_turns)` | Design 4.2: `[{session, turn, after}]` → `(session_id, turn, controls)`. |
| `cms_turn_end(p_session, p_turn, p_cursor, p_result, p_carried)` | Design 4.2 outcome table (Spec FR-009), with `p_carried BIGINT[]` (amendment S1): when non-empty and `p_result <> 'error'`, one `session.carried_steers_closed` record for the seqs not yet closed, reason `stopped` or `ran`. Clears `active_turn_index` when it is this turn. Idempotent. |

`cms_turn_end` outcome order (design 4.2, Spec FR-009):

```sql
CASE
    WHEN c.kind = 'stop' AND p_result IN ('stopped', 'error') THEN 'stopped'
    WHEN c.kind = 'stop'                                     THEN 'too_late'
    WHEN p_result = 'stopped'                                THEN 'not_delivered'
    WHEN c.seq <= COALESCE(p_cursor, 0)                      THEN 'delivered'
    WHEN v_stop_open                                         THEN 'not_delivered'
    ELSE 'carried'
END
```

Same signature. After the existing updates: `closeControls` (orchestration give-up) closes with reason `gave_up`; a terminal state closes with reason `terminal`, whoever writes it (plan P20, P17).

```diff
--- 0059
+++ 0082
@@
      WHERE session_id = p_session_id
        AND (p_updates ? 'model' OR p_updates ? 'reasoningEffort');
```

### `cms_create_session` — four revivable overloads, body modified

Each overload that writes the row itself first calls `cms_turn_lifetime_reset`, which acts only when the row exists and is soft-deleted (the revive branch). ### Paths audited for a reused session id (plan P19)

| Path | Fresh orchestration on the same id? | Covered by |
|---|---|---|
| System-session restart: archive, then `cms_create_session` | Yes | archive reset + overload reset |
| Soft delete, then `cms_create_session` with the same id | Yes | overload reset |
| `cms_create_session` on a live row | No (the upsert does nothing) | reset is a no-op |
| Session regeneration (transcript epochs) | No (same orchestration lifetime, turn index keeps rising) | not needed |
| A message to a session whose orchestration is terminal | Refused by the client before any start (`client.ts` terminal-orchestration checks) | not needed |

### `cms_get_session` — unchanged

Plan P5 proposed widening `cms_get_session`. `PgSessionCatalog.getSession` already joins the raw `sessions` row for columns added after the shared read procedure, to avoid a shape change that breaks re-application of earlier migrations. `turn_high` is read the same way: one column added to that existing join. No procedure shape changes.
