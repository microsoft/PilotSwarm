# Diff for migration 0084

Migration: `executable-package-reviews-0084.ts`, `executablePackageReviewsMigration`.
Design: `docs/proposals/executable-package-authorization.md`.
This companion documents the existing applied SQL; it does not amend migration 0084.

## Deploy and rollback requirements

Apply 0084–0088 in order with the current worker/provider code. Executable versions
without verified inspection remain pending; existing content is not grandfathered.
Activation is distinct from approval. Existing sessions require an explicit exact
binding rather than inference from the active version. Stop/fence legacy workers:
the 0085 cold-loader filter cannot stop their already-imported code, and 0086's
mixed-fleet gate requires externally verified process termination for unknown hosts.
Keep review, activation, binding and execution histories. There is no destructive
down migration; rolling code back does not authorize deleting evidence or bypassing
the fleet gate. Old consumers of the changed install-manifest return shape must be
upgraded together.

The inspection procedure checks canonical identity and inspection revision.
Decision/activation/rebind enforce exact-target CAS and append actor/reason audits.
Publication does not activate executable candidates. Target checks and bindings
preserve exact version/digest/agent/owner identity.

A guarded bootstrap also creates two missing-only stubs:
`cms_package_runtime_barrier() RETURNS VOID` (no-op) and
`cms_package_executable_eligible(TEXT,TEXT,TEXT) RETURNS BOOLEAN` (`FALSE`).
These allow safe standalone 0084 inspection/approval catalog setup but never
executable eligibility. 0085 replaces them with actual admission ordering and
eligibility; reapplication of 0084 cannot replace those real definitions.

| Trigger | Table/event | Function |
|---|---|---|

| `agent_package_version_immutable` | versions UPDATE | immutable artifact identity |
| `agent_package_activation_audit_append_only` | activation audit UPDATE/DELETE | append-only rejection |
| `agent_package_activation_guard` | packages UPDATE active_version_id | approved explicit activation guard |
| `session_agent_package_binding_audit_append_only` | binding audit UPDATE/DELETE | append-only rejection |
