# Diff for migration 0096

Migration file: `migrations/heartbeat-usage-0096.ts` — `heartbeatUsageMigration` (`cms-migrations.ts` entry `0096`, `heartbeat_usage`)

Claude keep-warm heartbeat usage. Each keep-warm ping is a model request that
reads the session's cached prompt, so each one gets a row of its own in
`provider_heartbeat_usage` and one `heartbeat` row in `provider_usage_ledger`,
charged to the provider it was sent to. A ping also adds its tokens to the
session's totals in `session_metrics`, as a turn's writeback does, and to
`heartbeat_count` and `heartbeat_nano_aiu`. `cms_get_session_metric_summary` is
not replaced: since 0022 it returns `SELECT *` of `session_metrics`, so it
returns the two new columns, which `SessionMetricSummary` carries as
`heartbeatCount` and `heartbeatNanoAiu`. The usage report functions count only
`usage_kind = 'turn'` rows as turns, so their token sums include pings.
`cms_get_session_tree_stats`, `cms_get_fleet_stats_by_agent` and
`cms_get_fleet_stats_totals` are dropped and created again with two more result
columns, `total_heartbeat_count` and `total_heartbeat_nano_aiu`, so the tree and
fleet stats report the counters. No existing row changes. Migrations 0001
through 0095 are not edited.

Writes one ping: a `provider_heartbeat_usage` row, the ping's tokens added to
the session's `session_metrics` totals with `heartbeat_count` and
`heartbeat_nano_aiu`, and one `heartbeat` row in `provider_usage_ledger` keyed
`(session_id, -ping_seq)`. The ledger row is charged to the provider of the
replayed request's model, resolved as a turn's admission resolves it, with the
session's owner and charge class; with no model, like the session's latest turn
row; when neither resolves, `unattributed`. A `user` row adds to
`provider_meters` and `provider_meters_user` as `cms_provider_settle_turn`
(0070) does. Returns the ping's `ping_seq`.
