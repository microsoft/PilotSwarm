# Migration 0089 — executable-only bindings and publisher approval status

## Added

- `cms_get_agent_package_version_review(TEXT) -> JSONB`: trusted internal exact
  version/digest review summary, used after an authorized publish or identical
  republish. Missing inspection is executable/unverified, never declarative.
- `cms_get_agent_package_review_status(TEXT,TEXT,TEXT,BOOLEAN) -> JSONB`: requires
  an authenticated package owner, package editor or administrator; resolves IDs
  or manageable names without enumerating other users' private packages. Returns
  active version and per-version digest, decision, executable classification and
  inspection reasons. It confers no admission or mutation authority.
- `cms_get_agent_packages_pinned_runtime_install_manifest()`: current enabled
  active versions plus approved executable versions retained by exact named
  bindings or active executable selection grants. Marks active versus retained.
  Legacy active-only manifests are unchanged.
- `cms_pkg_declarative_root(TEXT) -> BOOLEAN`: nonlocking authoritative check
  that a resolved named root is currently accessible and its active artifact is
  verified declarative, with no executable/unverifiable existing binding. Allows
  declarative roots to use separately exact-pinned executable selection grants
  without manufacturing a named-agent binding.

## Replaced

- `cms_get_session_agent_package_binding(TEXT)`: retains the nonlocking 0087
  authorization read and adds `executable`. Only an exact package/version/digest
  review with JSON boolean `false` qualifies as declarative; unknown or mismatched
  identity fails closed. Executable bindings also fail eligibility while the
  current active artifact is declarative, even before worker registry refresh.
- `cms_bind_new_session_agent_package(TEXT,TEXT,TEXT)`: verified declarative
  active versions return without creating or requiring a pin, including historical
  NULL-policy sessions. Existing rows are not deleted or rewritten. The session,
  binding, package lock order is unchanged. Executable initial binding and the
  historical explicit-rebind gate remain unchanged.

## Schema and operations

No tables, columns, constraints, indexes or triggers added, dropped or changed.
No review, activation, binding, grant or admission histories are rewritten.
Runtime admission implementations and barrier-first/nonlocking ordering are
not relaxed; named-binding eligibility adds the executable-to-declarative rebind
gate above. The runtime's missing-named-pin guard exempts only authoritative
declarative roots. Existing executable-root eligibility is checked before
cross-package selection grants as well as same-package invocations; target
version/digest, capability CAS and grant checks are unchanged.
Apply additively after 0084–0088 before updated workers/API servers.
Version-qualified worker tool/MCP/agent registries must be deployed together with
the new manifest consumer. Retained versions are not choices for new bindings.
Mixed-fleet and unresolved legacy-worker fencing gates remain mandatory; this
migration does not attest fleet completion. Roll forward; no destructive down or
audit deletion is supplied.
