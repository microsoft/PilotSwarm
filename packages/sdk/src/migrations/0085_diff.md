# Diff for candidate migration 0085

Migration file: `compute-native-0085.ts` - `computeNativeMigration`.
Numbering is provisional on the pinned compute branch and must be reconciled
before integration with current main. This file authorizes no schema deployment.

## Table changes

New tables: `compute_execution_admissions` (one durable per-session generation
and phase), `compute_execution_operations` (admitted work remains unresolved on
an unknown outcome), and `compute_turn_completions` (session/turn-key completion
deduplication with epoch/index identity and original receipt).

```sql
CREATE TABLE SCHEMA.compute_execution_admissions (
    session_id TEXT PRIMARY KEY,
    identity JSONB NOT NULL,
    phase TEXT NOT NULL CHECK (phase IN ('active','sealed','committed','unknown','released')),
    binding JSONB,
    reconcile_requested BOOLEAN NOT NULL DEFAULT FALSE,
    detail TEXT,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE TABLE SCHEMA.compute_execution_operations (
    session_id TEXT NOT NULL REFERENCES SCHEMA.compute_execution_admissions(session_id),
    generation TEXT NOT NULL,
    operation_id TEXT NOT NULL,
    settled BOOLEAN NOT NULL DEFAULT FALSE,
    PRIMARY KEY (session_id, generation, operation_id)
);
CREATE TABLE SCHEMA.compute_turn_completions (
    session_id TEXT NOT NULL,
    turn_key TEXT NOT NULL,
    transcript_epoch INTEGER NOT NULL,
    turn_index INTEGER NOT NULL,
    receipt JSONB NOT NULL,
    PRIMARY KEY (session_id, turn_key)
);
```

## New indexes

Primary keys on session, session/generation/operation, and session/turn key.

## Function changes

New stored procedures implement acquire, begin/end operation, seal/phase
transition, inspect, frozen charge identity and atomic native completion.
No historical procedure is replaced. Completion calls the existing
`cms_complete_turn_writeback` (baseline 0082) and `cms_provider_settle_turn`
(baseline 0070) inside the same transaction, once per native completion key.
The originally admitted absolute ledger index is translated under the locked
session row; recovery does not select today's accounting identity.

```diff
+ cms_compute_execution_acquire(identity JSONB) RETURNS VOID
+ cms_compute_execution_begin(identity JSONB, operation_id TEXT) RETURNS VOID
+ cms_compute_execution_end(identity JSONB, operation_id TEXT, success BOOLEAN) RETURNS VOID
+ cms_compute_execution_phase(identity JSONB, phase TEXT) RETURNS VOID
+ cms_compute_execution_inspect(session_id TEXT) RETURNS JSONB
+ cms_compute_execution_failure(identity JSONB, detail TEXT) RETURNS VOID

+ cms_compute_execution_reconcile_requests() RETURNS TABLE(status JSONB)
+ cms_compute_execution_reconciled(identity JSONB) RETURNS BOOLEAN
```

Legacy/local writeback and snapshot envelopes remain unchanged when no native
receipt is present. A failed operation does not silently expire its generation;
it remains unknown and prevents conflicting replacement.
Failure observations persist the authority detail and a deduplicated
`session.error` event. A stopped receipt preserves the filtered original
stopped outcome, including snapshot/workspace metadata, for activity replay
and turn-control closure without another runtime/provider admission.
Only the reserved publication/completion operations for a validated winning
receipt are settled by completion recovery. Other unresolved work is never
cleared. Allocation identity survives generation acquisition until the next
binding is recorded; known runtime generation is checked during reconciliation.
Released generations cannot be reopened by late phase, operation-completion or
failure callbacks; repeating the same release is harmless.
