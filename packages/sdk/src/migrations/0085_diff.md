## Deploy and rollback requirements

Ship 0084–0088 and compatible runtime workers together. This migration's
legacy-loader filter prevents **new cold imports**, not existing executable
processes. Stop/fence old workers and retain their evidence; 0086 completes the
mixed-fleet gate. A lease is admission liveness, never proof of process exit.
There is no destructive down migration: preserve registrations and audits when
rolling code back and keep executable admission disabled on an incompatible fleet.

A guarded `DO` bootstrap creates `cms_package_runtime_fleet_eligible() RETURNS
BOOLEAN` with `SELECT TRUE` only if absent, so reapplication cannot replace
0086's real gate. The barrier uses a schema-specific transaction advisory lock.
Executable eligibility additionally requires approved exact digest and verified
runtime policy. Mutations request denial-first fences and advance appropriate
epochs/registry state before committing.
