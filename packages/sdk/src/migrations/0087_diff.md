# Diff for migration 0087

Migration: `package-review-remediation-0087.ts`, `packageReviewRemediationMigration`.
Design: `docs/proposals/executable-package-authorization.md`.
This companion documents the already-applied migration without changing it.

## Deploy, table and rollback requirements

No tables, columns, indexes or triggers change. Deploy with 0084–0088 and matching
providers; legacy pin APIs may still pin verified declarative packages, never
executable or uninspected versions (including already-approved ones). Use the
explicit administrator exact-content activation path for executable versions.
Retain the 0086 mixed-fleet/legacy fencing gate and all audit/binding history.
There is no destructive down migration. Rolling back to a locking binding reader
would restore the documented writer/barrier lock inversion and is not safe
qualification for executable admission.

## New function

```diff
+cms_read_session_package_target(TEXT,TEXT,TEXT,TEXT,TEXT) RETURNS JSONB
```

This `STABLE` function performs the current live root/owner/package/version/
inspection/agent checks using ordinary MVCC reads, without tuple locks.
Binding/rebind mutations still call the locking assertion. Admission reads call
the nonlocking target reader under the authoritative barrier, allowing a writer
that already holds a metadata tuple lock to order after admission without a
deadlock. Runtime-registration locking is separate and retained.
