# Migration 0091 — advisory package review reports

Advisory only. A report is written by the `package-reviewer` agent for an
administrator. Nothing in this migration changes review, activation, binding,
grant, admission or fencing state, and no existing row is rewritten.

## Added

- Table `agent_package_review_reports`: one row per submitted report, keyed by
  the exact candidate (`package_id`, `version_id`, `candidate_sha256`) and the
  exact baseline (`baseline_version_id`, `baseline_sha256`, both `NULL` for a
  new package). It records the reviewer `session_id`, the author principal
  (`author_provider`, `author_subject`), the JSON `report` and `created_at`.
  `version_id` references `agent_package_versions` with `ON DELETE CASCADE`, so
  deleting a package version also deletes its reports. Checks: digests are
  64-character lowercase hex; baseline version and digest are both set or both
  `NULL`; the baseline is not the candidate; the report is a JSON object of at
  most 256 KiB with no `verdict`, `decision`, `approved`, `approval` or
  `rejected` key.
- Index `agent_package_review_reports_candidate` on
  (`version_id`, `candidate_sha256`, `created_at DESC`).
- `cms_put_agent_package_review_report(TEXT,TEXT,TEXT,TEXT,TEXT,TEXT,JSONB,TEXT,TEXT,BOOLEAN) -> BIGINT`:
  package ID, version ID, candidate digest, baseline version ID, baseline
  digest, session ID, report, provider, subject, administrator flag. Refuses a
  non-administrator or an empty principal, a candidate that is not `pending`
  with this exact digest, and a baseline that is not another exact version of
  the same package. Appends; it never updates or deletes.
- `cms_get_agent_package_review_report(TEXT,TEXT,TEXT,TEXT,TEXT,BOOLEAN) -> JSONB`:
  the newest report for the exact candidate and baseline, and only while the
  candidate is still `pending` with that digest; otherwise `NULL`.
  Administrator only. The management API additionally passes the baseline the
  review policy selects now, so a report written against an older baseline is
  hidden.

## Replaced

None.

## Schema and operations

Additive: one table, one index and two functions. Creating the foreign key
takes a brief `SHARE ROW EXCLUSIVE` lock on `agent_package_versions` while the
empty table is created; no rows are scanned. No retention job is added; reports
accumulate per candidate until the version is deleted or a later cleanup
migration. Reapplying the migration is idempotent.
