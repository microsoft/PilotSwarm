# Diff for migration 0086

Migration: `package-runtime-0086.ts`, `packageRuntimeCompletionMigration`.
Design: `docs/proposals/executable-package-authorization.md`.
This companion documents applied SQL; no behavior is amended here.

## Deploy and rollback requirements

Apply 0084–0088 in order with protocol-1 workers. Existing workers and orphan
agent-worker rows without that protocol are inserted into the legacy inventory
as **unverified**. An unknown/unreachable worker blocks executable activation
until trusted control-plane evidence establishes its process termination. Never
delete legacy rows or fabricate evidence to unblock activation. Expiry alone
does not acknowledge fencing. Preserve process identity, grant, audit and legacy
evidence across upgrades/rollback. No destructive down migration is provided.

`cms_package_runtime_fleet_eligible` replaces the conditional 0085 bootstrap
definition (`SELECT TRUE`) with `NOT EXISTS(SELECT 1 FROM
SCHEMA.package_runtime_legacy_workers WHERE state<>'fenced')`. The bootstrap is
inside a guarded `DO`, not an unconditional top-level function replacement.
Workers without protocol 1 reset their legacy evidence and request active fences.
Grant/owner/capability/lifecycle/configuration changes fence affected package
generations and invalidate registry state without deleting prior histories.

Normalized actual `diff -u` of the conditional bootstrap definition:
