# Migration 0086: Optional MoTD scheduling

Keeps `from_at` required in storage: an omitted start becomes server creation
time. Makes `to_at` nullable. A missing end means open-ended. Existing rows,
pictures, dismissals and earlier migration records are not changed.

Replaces the create, current, list and JSON functions. Active rows use
`GREATEST(from_at, created_at)` descending, then message ID descending.
Current still filters viewer dismissals. Readers still cannot list or load
future-scheduled announcements. The image, create/delete admin and dismissal
security rules from 0084/0085 remain.

Create accepts optional `startsAt` and `endsAt`, with legacy `fromAt` and
`toAt` aliases. Supplied ends must be in the future. If both requested times
exist, end must be after start. Retry receipts are checked before expiration,
so identical retries of an expired committed message remain idempotent.
Receipt hashes encode timestamp instants as Unix seconds, independently of
the SQL connection's time zone. Legacy receipt hashes remain accepted.
